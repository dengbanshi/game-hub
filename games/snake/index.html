贪吃蛇

分数0
最高0

方向键或 WASD 转向，空格暂停，R 重开。撞墙和撞自己都算结束，蛇身越长跑得越快。

这是什么机制

贪吃蛇是 Agent 循环的最小原型：读状态 → 选动作 → 承担后果 → 状态改变，一直重复到终止。整个循环里没有任何一步可以跳过，也没有任何一步能反悔。

真实 Agent 的 loop 也是这四拍：观察环境、决定动作、执行、观察新状态。区别只是它的「状态」是上下文，它的「动作」是调工具，它的「后果」要等好几秒才知道。

你能学到什么

  • 你会看到动作延迟的代价：你按下的方向键不是立刻生效，而是排进队列、等下一帧才用上。操作越快越容易连按两次反向键，把自己送进死路。
  • 你会亲手制造「我已经决定了，但环境还没跟上」的典型 Agent 故障——这也是为什么真实系统要做动作去重和状态确认。
  • 速度随分数提升，意味着决策预算在收缩：同样的思考时间，越到后面越不够用。

玩法规则

  1. 方向键或 WASD 转向，空格暂停/继续，R 重新开始；手机滑动屏幕转向。
  2. 吃到食物得 10 分，蛇身变长，移动速度随之提升。
  3. 撞墙或撞到自己身体，本局结束。
  4. 转向请求会进队列（最多 2 个），下一帧只取第一个合法方向，反向操作会被忽略。

算分方式

  • 每个食物 10 分，没有连击加成。
  • 速度：初始 150ms 一帧，每 50 分加快 8ms，最快 70ms。
  • 最高分存在本浏览器。

想深一点

为什么代码里要用「方向队列」而不是「直接改方向」？如果直接改，玩家在一帧内连按 ←→，蛇会瞬间掉头撞上自己——这不是玩家手快，是系统没有把「意图」和「已执行的意图」分开。想想你的 Agent 里，哪一步也缺了这层分离。
