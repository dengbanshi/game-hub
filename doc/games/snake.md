# 贪吃蛇

方向键转向，吃食物变长，撞墙或撞自己结束。在这个仓库里，它是 **Agent 循环的最小原型**。

- 分类：`game`
- 入口：`games/snake/index.html`
- 帮助内容：游戏页内「? 玩法与原理」

---

## 1. 背后的机制

Agent 的循环只有四拍：

```
观察状态 → 决定动作 → 环境执行 → 观察新状态
```

贪吃蛇一字不差地是这个结构。它的「状态」是蛇身坐标和食物位置，「动作」是四个方向之一，「环境」是棋盘和碰撞规则。

更值钱的是它暴露了真实 Agent 系统里两个经常被忽略的问题：

**动作延迟。** 你按了方向键，蛇不是立刻转，而是等下一帧才用上。真实 Agent 里这个延迟可能是几百毫秒的 API 调用、几秒的工具执行。延迟期间你可能会再按一次，于是两个意图叠在一起。

**意图与已执行的意图必须分离。** 这就是代码里那个 `pending` 方向队列存在的理由。如果没有它、直接改 `dir`，你在一帧内连按 ← → 会让蛇瞬间掉头撞上自己。玩家会觉得是游戏 bug，其实是系统没有区分「我想转向」和「我已经转向」。

## 2. 能学到什么

- **你会看到动作延迟的代价。** 手速越快越容易出事，因为你排进去的意图是基于上一帧的状态做出的决策。
- **你会亲手制造「我以为已经生效了」的故障。** 这是 Agent 系统里最常见的 bug 类型之一，通常靠动作去重 + 状态确认来修。
- **你会体会到决策预算在收缩。** 速度随分数提升：同样的思考时间，越到后面越不够用。这就是为什么线上系统要在负载高时降低推理预算。
- **你会理解为什么动作队列要限长。** `pending.length < 2` 这个判断，等价于真实系统里的「输入背压」——不限制的话，用户的连续点击会让队列无限堆积，执行时用的全是过期意图。

## 3. 玩法规则

1. 方向键或 WASD 转向，空格暂停/继续，R 重新开始；手机滑动屏幕转向。
2. 吃到食物得 10 分，蛇身变长。
3. 撞墙或撞到自己身体，本局结束。
4. 转向请求进队列（最多 2 个），下一帧只取第一个合法方向。反向 180° 的请求会被忽略——这不是防呆，是防止「瞬间掉头」这个物理上不可能的动作。
5. 速度：初始 150ms 一帧，每 50 分加快 8ms，最快 70ms。

## 4. 代码设计

两个文件：`index.html`（结构 + 样式 + 帮助内容）与 `game.js`（循环、渲染、复盘，约 350 行）。用 `setTimeout` 递归而不是 `setInterval`：

```js
function tick() {
  if (state !== 'running') return;
  // …移动、判定、绘制…
  timer = setTimeout(tick, speed());   // 每帧重新按当前分数算速度
}
```

用递归 `setTimeout` 而不是 `setInterval`，有两个原因：

1. **速度是动态的。** `setInterval` 的间隔在创建时就固定了，改速度要清掉重建。
2. **不会堆积。** 如果某一帧执行时间超过间隔，`setInterval` 会把回调排队，越排越多；`setTimeout` 是执行完再排下一次，天然不会积压。

方向队列的消费逻辑在 `tick()` 开头：

```js
while (pending.length) {
  const d = pending.shift();
  if (d.x === -dir.x && d.y === -dir.y) continue;   // 反向，丢弃
  if (d.x === dir.x && d.y === dir.y) continue;     // 同向，无意义
  dir = d;
  break;                                            // 一帧只吃一个意图
}
```

### 已知取舍

- **没有 AI 模式。** 加一个自动寻路会让它变成「看 AI 玩」，反而失去了「你要为延迟负责」的体感。复盘里的机械蛇只在结束后跑，不参与你这一局。
- **碰撞检测是 O(n) 的 `some()`。** 蛇最长 400 格，每帧扫一遍完全够用。上 `Set` 是过度设计。
- **随机数从 `Math.random()` 改成了种子 PRNG（`mulberry32`）。** 同 `g2048`：反事实要让机械蛇从同一个开局重跑，随机流必须可复现。种子存在状态里，也显示在面板右上角。

## 5. 复盘面板

由 `shared/review-panel.js` 渲染，本游戏只提供数据。

| 段 | 内容 |
| --- | --- |
| 判定 | 按得分分四档：`≥300` / `≥100` / `≥30` / 其余，各配一句诊断 |
| 指标 | 得分、蛇长、存活帧数、转向次数 |
| 归因 | 三条：存活概况、转向频率（平均每几帧改一次方向）、致命那一步的死因与「方向是否来自队列」 |
| 反事实 | 同一个种子（第一条食物位置相同），换成「只朝食物直线走、只在下一步会撞时改向」的机械蛇重跑；外加 10 个开局的中位分 |
| 建议 | 一条：队列误判 / 转向太频 / 机械蛇更强 / 已经赢过它，四选一 |

**「方向是否来自队列」这个字段是专门为教学加的**：`tick()` 消费队列时记一个 `fromQueue`，死亡时写进统计。为真就说明玩家以为的当前方向和实际执行的方向不一致——这正是本文 §1 讲的「意图与已执行意图没分开」的现场证据。没有这个字段，复盘只能笼统说「你撞墙了」，那等于没说。

**反事实的公平性要写在面板里**：机械蛇不受帧率限制、也不需要反应时间，所以它更强是正常的。这一点写在面板 footer 里，避免玩家把结论读成「你手速不行」。这里真正比的是：每次转向时有没有做那一次安全检查。
