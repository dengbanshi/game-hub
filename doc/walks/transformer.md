# Transformer 全流程

一句话：把「一段文字变成一个词」这条链路拆成 12 步，每一步都能拧参数，看它怎么改变后面的结果。

- 形态：`walk`
- 分类：`inference`
- 入口：`walks/transformer/index.html`
- 步骤：12 步
- 在线：https://dengbanshi.github.io/game-hub/ （大厅里点开）

## 1. 这条链路在讲什么

大多数讲解只挑一道工序讲透：注意力机制讲一节课、KV cache 单独一篇、采样策略再单独一篇。结果是每道工序都懂一点，却说不清它们怎么串起来，也说不清**哪一道最贵、哪一道错了会毁掉什么**。

这个图解坚持用同一个提示词 `解释 KV cache 为什么重要` 走完全程，中途不换例子。因为只有不换例子，读者才能把「第 2 步把分词粒度改成单字」和「第 4 步的矩阵从 5×5 变成 17×17」对上号——一旦换了例子，那些数字就成了两组互不相干的插图。

链路分四段：**输入**（提示词 → 分词 → 嵌入）、**主干**（注意力 → 归一化 → 前馈 → 层堆叠，整块重复 N 次）、**输出**（输出头 → 采样）、**解码**（prefill/decode → KV cache → 投机解码）。

前三段决定「准不准」，第四段决定「快不快」。这两个问题在大模型工程里几乎从不同时出现，但对读者来说它们是一条线上的两截——中间那段解码，正是「模型答得对但慢得没法用」的全部由来。

## 2. 能看出什么

- **把分词粒度从子词换成单字**，序列长度从 5 变成 17，注意力矩阵从 25 格变成 289 格。长度只翻了 3.4 倍，代价翻了 11.6 倍——这就是 O(n²) 最直白的样子。
- **关掉位置编码**，`猫追狗` 和 `狗追猫` 在模型眼里变成同一个东西。这是「为什么需要位置编码」最短的证明，比任何公式都直接。
- **关掉因果掩码**，第一个 token 能直接看到「重要」。读者会立刻明白为什么训练时不能这样——它学会的是抄答案，而推理时抄不到。
- **把温度从 0 拖到 2**，会看到候选的**顺序一次都没变**，变的只是它们之间的差距。这一步专门用来拆「温度让模型更聪明」这个误解。
- **把层数从 8 拖到 48**，参数量和 KV cache 一起线性上涨；再把上下文拖到 128k，KV cache 会超过模型权重本身——长上下文贵在哪里，这一屏说得最清楚。

## 4. 代码设计

三个文件，`walk.js` 一个就够（约 700 行，主要是 12 个 `draw`）：

```
walks/transformer/
├── index.html   骨架 + 帮助内容
├── walk.css     只放本图解独有的画法（气泡 / token / 向量格 / 矩阵 / 时间轴）
└── walk.js      数据 → 纯函数 → 绘制辅助 → steps → mount
```

`walk.js` 分五层：

1. **数据**：`TOKENS`（固定的 5 个 token）、`CANDIDATES`（8 个候选及 logits）、`ATTN_SCORE`（5×5 对称打分表）、`D_MODEL = 4096`、`VOCAB = 128000`。
2. **纯函数**：`softmaxAt`、`attentionRow`、`truncate`、`sampleFrom`、`kvPerToken`、`expectedAdvance`。全部不碰 DOM，可以单独跑。
3. **绘制辅助**：只有 `vecStrip`（本图解独有的向量格）。指标卡 / 条形图 / 流程块 / 判断条走 `GameWalk.ui`，不重写。
4. **`steps` 数组**：12 个对象，字段见 ARCHITECTURE §6.8。
5. **`GameWalk.mount({...})`**：一次性注册全部参数与步骤。

两个关键实现细节：

```js
// 必须先减最大值。T 很小时 exp(z/T) 会溢出成 Infinity，Infinity/Infinity 得到 NaN，
// 整屏数字会变成 NaN —— 第一版就是这样白了一片。
function softmaxAt(logits, temperature) {
  const t = Math.max(temperature, 0.01);
  const max = Math.max.apply(null, logits);
  const exps = logits.map((z) => Math.exp((z - max) / t));
  const sum = exps.reduce((a, b) => a + b, 0);
  return exps.map((e) => e / sum);
}
```

### 哪些数字是真算的，哪些是示意的

| 数字 | 来源 | 真实 / 示意 |
| --- | --- | --- |
| 参数量 6.97B、权重 13.9 GB | `layers × (4d² + 2·ratio·d²) + vocab·d`，代入 d=4096 / vocab=128k 实算 | 真实 |
| 每 token 的 KV = 512 KB | `2 × layers × d × 2 bytes`，与 7B 模型公开数字吻合 | 真实 |
| 128k 上下文的 KV ≈ 62.5 GB | 上一行 × 131072 | 真实（线性外推） |
| 前馈参数占比 ≈ 67% | 实算 | 真实 |
| 注意力 5×5 权重矩阵 | 手工挑的对称打分表（KV↔cache 权重大） | **示意** |
| 8 个候选的 logits | 手工设定，量级参考真实分布 | **示意** |
| 嵌入向量（4~8 维） | 由 token 文本哈希派生，刷新不变 | **示意** |
| 投机解码的加速比 | `(1−a^(k+1))/(1−a) ÷ (1+0.05k+0.004k²)`，与投机采样游戏同源 | 真实 |

示意部分集中在「分布长什么样」，真实部分集中在「规模有多大」。这个分工是有意的：分布的**形状**靠挑才讲得清，规模的**量级**必须真算，否则读者会把科幻数字当成事实引用。

### 已知取舍

- 提示词固定不可编辑。允许随意改文本会让第 8 步的词表 logits 和第 4 步的注意力矩阵全部失效，因为那些数字是照着这一段话准备的。
- 维度压到 4~8。真实是 4096 维，但 softmax / 归一化 / 采样的算术性质与维度无关。
- 只画单头注意力。多头会让矩阵变成三维，这一屏已经够满了；多头的信息放在文案里。
- 归一化两屏用的是同一个手写向量，不是从第 3 步真实传下来的——图解按步骤独立渲染，没有跨步骤的状态传递，这是外壳的刻意设计（任何一步都能直接跳进去看）。
